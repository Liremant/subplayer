# subplayer

**Русский** · [English](README.md)

[![Лицензия: AGPL-3.0](https://img.shields.io/badge/license-AGPL--3.0-blue.svg)](LICENSE)
[![Последний релиз](https://img.shields.io/github/v/release/Liremant/subplayer)](https://github.com/Liremant/subplayer/releases/latest)

Самостоятельно размещаемый видеоплеер для личной медиатеки, построенный вокруг
двуязычных субтитров. Отдаёт локальные файлы по HTTP, показывает оба языка одновременно
и даёт инструменты, чтобы подогнать чужие субтитры под конкретный релиз.

Приложение рассчитано на одного пользователя в локальной сети. В нём нет учётных записей,
базы данных и внешнего каталога метаданных: библиотека — это файловая система.

## Возможности

**Двойные субтитры.** Оба языка отображаются одновременно из одного файла субтитров.
Доступны четыре режима: оба, только оригинал, только перевод, выключены.

**Сдвиг тайминга.** Субтитры сдвигаются шагом 0.5 с прямо во время просмотра — это
основной способ согласовать дорожку с другим релизом. Сдвиг хранится отдельно для каждого
видео и применяется и к оверлею, и к списку реплик.

**Панель реплик.** Все реплики перечислены рядом с видео. Клик по реплике перематывает на
неё; активная реплика подсвечена, удерживается в вертикальном центре списка, и подсветка
не гаснет в паузах между репликами, пока не начнётся следующая.

**Поиск по субтитрам.** Поиск по обоим языкам с подсветкой совпадений и переходом к
найденной реплике.

**Свободное положение субтитров.** Размер и позиция не привязаны к фиксированной раскладке.
Блок размещается в любой точке кадра в процентах от его размеров — ползунками или
перетаскиванием мышью.

**Фуллскрин с колонкой диалогов.** В полноэкранном режиме видео и прокручиваемая колонка
диалогов располагаются рядом, поэтому субтитры остаются читаемыми и не закрывают кадр.

**Каталог.** Фильмы и сериалы представлены сеткой карточек с обложками, прогрессом
просмотра, поиском и сортировкой. Эпизоды группируются в сериалы автоматически.

**Обложки.** Обложку можно положить локальным файлом либо найти по названию и скачать из
TVmaze (сериалы) или каталога iTunes (фильмы).

## Требования

| | Linux | macOS | Windows |
|---|---|---|---|
| Rust | [rustup](https://rustup.rs) | [rustup](https://rustup.rs) | [rustup](https://rustup.rs) с инструментарием MSVC |
| Node.js 20+ | пакет дистрибутива или [nodejs.org](https://nodejs.org) | [nodejs.org](https://nodejs.org) или `brew install node` | [nodejs.org](https://nodejs.org) |
| pnpm | `corepack enable pnpm` | `corepack enable pnpm` | `corepack enable pnpm` |
| ffmpeg | `pacman -S ffmpeg` / `apt install ffmpeg` | `brew install ffmpeg` | `winget install Gyan.FFmpeg` |

ffmpeg требуется только для импорта медиа (`scripts/import.sh`) и генерации демонстрационной
библиотеки. Для воспроизведения готовых MP4 он не нужен.

## Установка

Готовые архивы для Linux, macOS и Windows приложены к каждому
[релизу](https://github.com/Liremant/subplayer/releases). Распакуйте архив, положите медиа в
`media/`, запустите бинарник `subplayer` и откройте <http://127.0.0.1:3000>. Сборка фронтенда
уже включена, собирать ничего не требуется.

### Сборка из исходников

Фронтенд собирается до сервера: бинарник читает `web/dist` с диска, а не содержит его внутри.

#### Linux и macOS

```sh
git clone https://github.com/Liremant/subplayer.git
cd subplayer

cd web && pnpm install && pnpm build && cd ..
cargo build --release

./target/release/subplayer
```

В macOS при отсутствии линкера установите инструменты командной строки Xcode:

```sh
xcode-select --install
```

Целевая платформа выбирается автоматически, включая Apple Silicon.

#### Windows

Требуется инструментарий MSVC. Если Rust установлен без него:

```powershell
rustup default stable-msvc
```

Если C++ build tools отсутствуют, установите «Build Tools for Visual Studio» с компонентом
«Desktop development with C++», затем:

```powershell
git clone https://github.com/Liremant/subplayer.git
cd subplayer

cd web; pnpm install; pnpm build; cd ..
cargo build --release

.\target\release\subplayer.exe
```

Windows PowerShell версий до 7 не принимает `&&` как разделитель команд: используйте `;`,
как показано выше, либо выполняйте команды из Git Bash или WSL.

Пути обрабатываются через `std::path::Path`, поэтому `\` и `/` взаимозаменяемы. Чтобы
использовать библиотеку на другом диске, укажите абсолютный путь в `SUBPLAYER_MEDIA`.

## Настройка

Сервер настраивается переменными окружения.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `SUBPLAYER_MEDIA` | `media` | Корневой каталог медиатеки |
| `SUBPLAYER_DATA` | `data` | Прогресс просмотра, настройки, скачанные обложки |
| `SUBPLAYER_DIST` | `web/dist` | Собранный фронтенд |
| `SUBPLAYER_PORT` | `3000` | Порт прослушивания |

Сервер слушает только `127.0.0.1` и намеренно недоступен с других хостов. Про удалённый
доступ — в разделе [Развёртывание](#развёртывание).

## Раскладка библиотеки

```
media/
  Breaking Bad/S02/E05/
    video.mp4        # h264 + aac, атом moov в начале файла
    subs.vtt         # оба языка, оригинал в <b>
    meta.json        # опционально
  Dune.2021.1080p/
    video.mp4
    subs.vtt
    poster.jpg       # опционально
```

Дерево каталогов сканируется рекурсивно: любой каталог с видеофайлом становится записью
библиотеки, а эпизоды группируются в сериал по имени. Имена вида
`Dune.2021.1080p.BluRay.x264-GRP` разбираются автоматически: название, год и теги релиза
разделяются без дополнительной настройки.

Подробное руководство по именованию файлов, `meta.json`, обложкам и перекодированию —
[docs/ADDING-MEDIA.ru.md](docs/ADDING-MEDIA.ru.md).

## Субтитры

Для каждого видео используется один файл субтитров, в котором каждая реплика содержит оба
языка, а оригинал размечен тегом `<b>`:

```
1
00:00:01.000 --> 00:00:03.000
<b>I am the one who knocks</b>
Я тот, кто стучится
```

Один файл выбран осознанно. Два языка нарезаны на реплики по-разному, поэтому объединение
двух независимых дорожек по индексу или по времени разваливается на реальных данных; один
файл даёт единственный источник истины для нарезки.

Два файла SRT можно объединить в этот формат:

```sh
python3 scripts/merge-subs.py original.srt translation.srt -o subs.vtt
```

Скрипт автоматически оценивает сдвиг и растяжение между релизами. Если тайминги уже
совпадают, передайте `--no-warp`.

## Использование

1. Поместите медиа в каталог, указанный в `SUBPLAYER_MEDIA`.
2. Откройте <http://127.0.0.1:3000>. Каталог пересканируется на каждый запрос; после
   добавления файлов перезапуск не требуется.
3. Выберите запись, чтобы открыть плеер. Фильм открывает плеер сразу; сериал открывает
   страницу со списком эпизодов по сезонам.

Позиция воспроизведения сохраняется каждые пять секунд во время просмотра, при паузе и при
закрытии страницы. При повторном открытии видео воспроизведение продолжается с сохранённого
места.

Выравнивание субтитров, режим отображения, размер и положение настраиваются в панели
настроек плеера либо горячими клавишами. Сдвиг тайминга хранится отдельно для каждого видео,
остальные настройки субтитров — глобальные значения по умолчанию.

## Горячие клавиши

Клавиши сопоставляются по физическому положению, поэтому работают одинаково на любой
раскладке, включая кириллическую.

| Клавиша | Действие |
|---|---|
| `Space`, `K` | Пауза |
| `←` `→` | Перемотка −5 с / +5 с |
| `J` `L` | Перемотка −10 с / +10 с |
| `↑` `↓` | Громкость |
| `0`–`9` | Переход к 10 %…90 % |
| `Home` `End` | Начало / конец |
| `M` | Звук |
| `F` | Полный экран |
| `I` | Картинка в картинке |
| `C` | Переключение режима субтитров |
| `G` | Перетаскивание субтитров |
| `[` `]` | Сдвиг субтитров −0.5 с / +0.5 с |
| `,` `.` | Скорость воспроизведения |

## HTTP API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/library` | `{ movies, series }`, у каждого эпизода свой прогресс |
| GET, PUT | `/api/settings` | Глобальные настройки |
| POST | `/api/progress` | `{ id, t, dur, shift }` |
| GET | `/api/posters/search?kind=&q=` | Варианты обложек |
| POST | `/api/posters` | Загрузить выбранную обложку в `data/posters/` |
| GET | `/media/<path>` | Медиафайлы с поддержкой `Range` |
| GET | `/posters/<file>` | Скачанные обложки |

## Разработка

Запустите бэкенд и dev-сервер Vite одновременно. Vite отдаёт фронтенд с горячей заменой
модулей и проксирует `/api` и `/media` на бэкенд.

```sh
cargo run                          # терминал 1 — порт 3000
cd web && pnpm dev                 # терминал 2 — порт 5173
```

Откройте <http://localhost:5173>.

Перед отправкой изменений:

```sh
cargo test
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cd web && npx tsc --noEmit && pnpm build
```

Соглашения репозитория описаны в [AGENTS.md](AGENTS.md). Каждая функциональность
разрабатывается в отдельной ветке и вливается в `main`.

## Развёртывание

### systemd (Linux)

```ini
# ~/.config/systemd/user/subplayer.service
[Unit]
Description=subplayer
After=network.target

[Service]
WorkingDirectory=%h/Projects/subplayer
ExecStart=%h/Projects/subplayer/target/release/subplayer
Restart=always
RestartSec=2

[Install]
WantedBy=default.target
```

```sh
systemctl --user daemon-reload
systemctl --user enable --now subplayer
journalctl --user -u subplayer -f
```

После пересборки перезапустите юнит: `systemctl --user restart subplayer`. Если `cargo run`
сообщает `AddrInUse`, порт уже занят юнитом; корректное решение — перезапуск юнита, так как
он настроен на автоматический перезапуск.

В macOS используется `launchd`, в Windows — Планировщик задач или обёртка службы вроде NSSM.
Файлы юнитов для этих платформ в репозиторий не входят.

### Удалённый доступ

Сервер слушает только интерфейс loopback. Для доступа к библиотеке с других устройств
разместите перед ним обратный прокси или используйте mesh-VPN. Аутентификация не
реализована и не планируется: контроль доступа передаётся внешнему слою.

Для запуска в контейнере требуется адрес привязки, отличный от `127.0.0.1`; сейчас он жёстко
задан в `src/main.rs`, потребуется переменная `SUBPLAYER_HOST`.
